# KB 소상공인 생애주기 금융지원 AI 에이전트

예비창업자와 기존 소상공인이 창업 준비부터 운영 개선까지 사용할 수 있도록 만든 독립 실행형 프로토타입입니다. 사업 단계와 업종, 자금·비용 정보를 입력하면 결정론적 금융 분석, 공식 정책자금 검색, 네 전문가 관점의 의견, 감독 에이전트의 우선 실행 제안을 제공합니다.

## 개인 역할

기획, 아키텍처 설계, 프론트엔드·백엔드 구현, 금융 분석 로직, 정책 데이터베이스, 에이전트 오케스트레이션, 보안 경계, 자동화 테스트, 제출 문서화를 처음부터 끝까지 단독으로 수행했습니다.

## 해결하려는 문제

- 창업 준비와 운영 단계마다 필요한 금융 판단 기준이 달라 한 화면에서 비교하기 어렵습니다.
- 정책자금 정보는 공식 출처와 자격 조건이 함께 제시되지 않으면 과장된 승인 가능성으로 오해될 수 있습니다.
- 생성형 모델이 금융 수치나 정책명을 자유롭게 생성하면 사실성·보안 위험이 커집니다.

## 주요 기능

- 창업 경로: 예산, 항목별 비용, 자기자본, 부족 자금, 권장 버퍼 계산
- 운영 경로: 신고 매출·이익과 독립 계산 결과 비교, 비용 비율과 현금흐름 위험 확인
- 정책 검색: SQLite에 저장한 공식 출처 스냅샷만 검색하고 불확실한 자격은 `CHECK_REQUIRED`로 표시
- 전문가 협의: 시장·운영·재무·정책 전문가와 감독 에이전트가 검증된 근거만 사용
- 안전한 인계: 사용자가 명시적으로 동의한 경우에만 필요한 근거를 전문가 상담 흐름으로 전달
- 반응형 UI: 데스크톱·모바일 입력, 분석 결과, 정책 비교, 근거 상세 화면 지원

## 요청 처리 흐름

```text
사용자 입력
  → 입력 스키마 검증
  → 결정론적 금융 계산
  → SQLite 공식 정책 검색
  → 상권 데이터 상태·출처 검증
  → Canonical Evidence Registry 생성
  → 시장/운영/재무/정책 전문가 분석
  → Opinion Verifier 재검증
  → Supervisor가 최대 3개 행동 제안
  → 신뢰된 템플릿으로 UI 출력
```

## 신뢰·보안 경계

- 금융 산술과 비율 판정은 언어 모델이 아닌 JavaScript 코드가 수행합니다.
- 정책 후보는 SQLite가 발급한 근거 권한과 공식 URL·검증일을 가져야 합니다.
- 전문가 에이전트는 허용된 주장·행동 코드와 자신에게 허용된 근거만 선택할 수 있습니다.
- 검증기는 알 수 없는 근거, 임의 정책명·URL, 승인 보장, 민감 문자열, 근거 없는 숫자 서술을 거부합니다.
- 외부 모델로 전달 가능한 데이터와 내부 전용 데이터를 분류하고 원시 식별정보·거래 텍스트의 외부 전달을 차단합니다.

## 기술 스택

- Runtime: Node.js 24+, JavaScript ES Modules
- Backend: `node:http`, REST API
- Data: SQLite (`node:sqlite`), JSON 공식 출처 스냅샷
- Frontend: Vanilla JavaScript, HTML, CSS
- Architecture: Multi-agent orchestration, evidence registry, policy matcher, opinion verifier, model gateway contract
- Test: `node:test`, Playwright 기반 데스크톱·모바일 E2E

## 실행 방법

외부 패키지 설치나 네트워크 연결 없이 실행할 수 있습니다.

```powershell
cd prototype
node scripts/init-policy-db.mjs --output database/policies.sqlite
npm.cmd test
npm.cmd start
```

브라우저에서 `http://127.0.0.1:4173`으로 접속합니다.

## 트러블슈팅: 시간 의존 테스트의 재현성

상권 데이터의 주간 유효기간이 지나면서 기준지수와 후보지 결과가 달라져 5개 테스트가 실패했습니다. 원인은 테스트 서버가 주입받은 시각 대신 `/api/analyze`에서 시스템 현재 시각을 직접 사용한 것이었습니다.

- 요청 처리기가 주입된 `now()`를 사용하도록 수정
- API·브라우저 E2E 테스트 시각을 `2026-08-03T00:00:00Z`로 고정
- 실제 운영의 데이터 만료 규칙은 유지하면서 전체 257개 테스트의 재현성을 확보

## 프로토타입과 프로덕션의 차이

- 현재 실행 결과는 결정론적 템플릿과 검증기로 생성됩니다.
- 실제 LLM은 설치·실행·평가하지 않았으며, 프로덕션에서는 기업 내부 로컬 LLM을 모델 게이트웨이 뒤에 연결하는 구조를 목표로 합니다.
- 주변 점포, 임대 매물, 신규 입점, 유동인구 등 실시간 상권 제공자는 `PLANNED_INTEGRATION` 상태입니다.
- 사업·거래·상권 데모는 합성 데이터이며, 업종 기준 범위는 공식 평균이 아닌 `PROTOTYPE_REFERENCE_RANGE`입니다.
- 정책 스냅샷은 공식 출처를 사용하지만 실제 승인 가능성을 보장하지 않습니다.
